## Instance launch settings (instance.json)

Only the `launcher.wrapperCommand` field differs from what Iroh needs; everything else is identical to the pack
(Fabric Loader 0.19.5, Java `/usr/lib/jvm/java-27-openjdk`, max heap 10240 MB, `-XX:+UseZGC -XX:SoftMaxHeapSize=8G ...`,
no GL context flags).

- Original (the pack's, and Vulkan's until today): `"wrapperCommand": "env MESA_LOADER_DRIVER_OVERRIDE=zink GALLIUM_DRIVER=zink"`.
  A manual ATLauncher launch of Vulkan with that would start Iroh with Mesa told to load Zink for any GL/EGL use. Iroh
  creates no GL context (GLFW NO_API), so it would probably run, but it hands a Zink driver override to a native Vulkan
  game and to every mod that probes GL.
- Applied to the Vulkan instance only: `"wrapperCommand": ""`. Diff against the snapshot: that one field, nothing else.
  Original text kept in `~/.local/share/atlauncher/instances/Vulkan/.iroh-wrapperCommand.orig`.
- `tools/disable-gl.sh` and `tools/restore-gl.sh` now do this clear/restore themselves (not run in this card, only
  `bash -n` checked).
- Consequence to remember: a NEW Proctor clone made from Vulkan after today is native GL / native Vulkan without a
  wrapper. GL clones of the pack must put the wrapper back (`PROCTOR_NO_WRAPPER` is no longer needed for Iroh clones).
  `iroh-gl`, `iroh-gl2` keep the Zink wrapper (made before the change).
