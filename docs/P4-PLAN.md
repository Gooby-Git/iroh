# P4-PLAN: upscaling (Phase 4) and frame generation (Phase 8) breakdown

Card P4-0, 2026-11-22; updated by card P4-2a (same day). Facts and the full API contract: `knowledge/fsr.md` section A (skill folder).

## Verdict
- FSR 3.1 upscaling on Linux needs **no Windows tool and no licence exception**. AMD SDK v1.1.4 (MIT, commit c6efa6bf) still has native Vulkan backend source with GLSL shaders; its Windows-only shader generator is replaced by a 150-line script around system `glslangValidator`. Built offline (compile+link only): `libffx_fsr3_vk.so` 4.6 MB with upscaler + frame interpolation + optical flow, no undefined symbols, 2968 SPIR-V blobs validated. Patch set vs pristine SDK: 3 files, 70 lines (context-size guard for Linux 4-byte `wchar_t`; two FSR 3.1.4 -> 3.1.6 shader back-ports). Version delivered is 3.1.4 host + 3.1.6 shaders (host deltas not fully audited).
- Binding: JNI shim (Java 21 has no final FFM; LWJGL has no FFX bindings), packaged like Vista's native lib (`natives/<os>-<arch>/`, extract + `System.load`).
- Frame generation: the SDK's swapchain proxy is Win32-only; the interpolation + optical-flow components are not, and build on Linux. Own present/pacing needed; gamescope behaviour UNVERIFIED.
- FSR 4 stays Windows-only (signed DLLs only); DLSS unchanged (UNTESTED label). One `Upscaler` interface serves all three.

## What the in-game card (P4-1) must provide to this interface
1. Device creation: enable `shaderStorageImageExtendedFormats`, `shaderStorageImageWriteWithoutFormat` (+ReadWithoutFormat for frame interpolation), subgroup basic+quad compute support is core 1.1 (check `VkPhysicalDeviceSubgroupProperties`); optionally shaderFloat16 + shaderInt16 + storageBuffer16BitAccess for the 16-bit permutations (verified identical output on lavapipe). `FsrUpscaler.create(..., shimFlags=NO_FP16)` otherwise.
2. Images in these layouts at dispatch: colour, depth (D32_SFLOAT, SAMPLED usage), motion vectors (R16G16_SFLOAT), masks: `SHADER_READ_ONLY_OPTIMAL`; output (STORAGE usage, RGBA16F or any storage format): `GENERAL`. FSR restores the same layouts. Depth is read through the SDK as an R32 view; D32S8 also works (stencil ignored).
3. Jitter: `JitterSequence.offset(frameIndex)` pixels; **verified on lavapipe: the image content must shift by +jitter pixels in x and in y** (sampling at `pixel + 0.5 - jitter`); with the opposite sign RMSE is 36% worse. In projection terms (SDK): NDC offset `(+2jx/W, -2jy/H)` for a y-up NDC; Iroh's flipped viewport makes this a sign to confirm with the replay harness (render a static checker with the real projection, two jitters, compare shift).
4. Motion vectors current -> previous position in render pixels (scale 1,1), unjittered; background 0; moving object `-velocity`. The test scene uses exactly this and shows no ghost trail.
5. Colour must be area-averaged per render pixel (mip-mapped textures, MSAA-like): point-sampled aliased content makes FSR reject its history (measured: FSR no better than bilinear on aliased 1-sample checker).
6. Report memory: `FsrUpscaler.memoryUsageBytes()` = {SDK internal, shim shared images}; measured 5.66 MB + 0.69 MB at 320x180 -> 640x360 and 63.0 MB + 11.1 MB at 1280x720 -> 1920x1080 (the estimate formula is within 18%); feed MemoryGuard before create.
7. Camera data: `cameraNear/Far/FovY` (real values), `frameTimeMs`, `reset` on world change / teleport / resize / first frame; sharpening 0..1 optional (RCAS pass).
8. Thread rule: render thread only, command buffer recording, create/destroy with the GPU idle.
9. For Navidson tier 1: the pack-cut input image must exist: the captured frame has `colortex3` ALL ZERO (post-mode capture saved only raster colour in `colortex0` + `depthtex0`), so a replay of the pack chain up to composite5 (P3-3) is needed to get the real upscale input offline.

## Phase 8 design note: Linux present path for frame generation (no implementation)
Goal: 2x displayed frames from the FSR frame-interpolation + optical-flow components (already built into `libiroh_fsr`), without the SDK's Win32-only swapchain proxy.
- **Frame flow** (render thread R, present thread P): R renders + upscales frame N (HUD-less colour at display size), computes optical flow N-1 -> N, interpolates image I(N-1,N) into its own image, draws the HUD on I and on N (HUD at native resolution, rendered once per target), submits one batch (signal timeline semaphore S_N), hands {I, N, S_N, timestamps} to P. P acquires a swapchain image, waits for the interpolated image, presents I at T_N + dt/2, then presents N at T_N + dt (dt = smoothed real frame time). One real frame of added latency (we must hold N until I is shown); Anti-Lag 2 (`VK_AMD_anti_lag`) on RADV compensates input latency; the combat feel check (P8-4) decides the default (off).
- **Pacing**: a state machine, not GPU-side pacing: target present time = previous real present + dt/2 for I; dt = EMA of real frame times over ~8 frames with spike rejection (>1.5x); if the interpolation is not ready by its slot it is DROPPED (present N only) and the counter reports it; stop interpolating when dt > 40 ms or on a reset (teleport, world change, resolution change, pause menu) and drop optical-flow history. The wait uses a timer thread with coarse sleep + short spin (like the SDK's busy-wait pacing, but never above one core's 25%); present modes: FIFO/mailbox as the swapchain gives; two presents per real frame need display rate >= 2x real frame rate, or the interpolated frames queue behind vsync (UNVERIFIED: measure `VK_KHR_present_wait`/`VK_EXT_present_timing` availability and the actual queue depth in the first guarded run).
- **gamescope / Wayland**: the swapchain belongs to gamescope's WSI layer (or the compositor's); we cannot assume exclusive timing. Rules: never present faster than the compositor drains (use `VK_KHR_present_id` + `present_wait` when exposed to bound the queue to 2 images); keep minImageCount 3; do not combine with the lsfg-vk layer (double generation); VRR stays untouched (owner: broken). Nothing here is verified: the first Proctor run must log acquire/present durations per frame and per-present timestamps to prove or kill the design.
- **Cards**: P8-0 [S] shared-resource plumbing (dilated depth/MVs from the upscaler into FI, optical-flow image + scene-change buffer, build already green); P8-1a [O] OF + FI dispatch and HUD composition, lavapipe golden = interpolated image of a pure-translation pair equals the half-step within tolerance (same harness as `fsrReplay`); P8-1b [O] present thread + pacing state machine with a deterministic unit test on a fake clock (drop/stop/reset rules) and one guarded Proctor timing run; P8-3 [S] anti-lag. FSR 4 frame generation: Windows only, signed DLL with its own swapchain.
